# PUBLISH_CHECKLIST.md

## Purpose

Pre-publish checklist for System Analysis Reference public surfaces.

Use this before turning `public/INDEX_COPY.md`, templates, timelines, evidence structures, or case-study materials into a live page or public reference library.

## Current public copy source

`public/INDEX_COPY.md`

## Publish posture

System Analysis Reference may publish as a neutral reference library for organizing evidence, timelines, claims, and observed system behavior.

It may carry:

- timeline templates
- evidence index templates
- claim-boundary worksheets
- source logs
- observation maps
- pattern analysis formats
- case-study structures
- procedural breakdowns

It should not become:

- Perspection governance
- Faceless Reclaimation testimony
- Trinity Framework doctrine
- raw legal accusation archive
- unsorted evidence dump
- public claim page without source separation

## Pre-publish checklist

Before publishing, confirm:

- [ ] The page identifies itself as System Analysis Reference.
- [ ] The page stays neutral and structural.
- [ ] Source, observation, interpretation, and claim are separated.
- [ ] Unsupported claims are labeled as unsupported.
- [ ] Confirmed claims have source support.
- [ ] Open questions are labeled as open questions.
- [ ] Personal identifiers are excluded unless intentionally necessary.
- [ ] Legal conclusions are not asserted without source support.
- [ ] The material does not become Faceless Reclaimation testimony.
- [ ] The material does not become Perspection governance.
- [ ] The material does not absorb the whole ecosystem.
- [ ] Related projects are labeled as related, not absorbed.

## Voice check

The page may be:

- neutral
- careful
- structural
- source-aware
- claim-bounded
- procedural
- evidence-oriented

The page should avoid becoming:

- accusatory by default
- dramatic
- testimony-heavy
- governance-heavy
- over-personalized
- unsourced
- legally conclusive without support
- a raw evidence dump

## Core separation rule

Every public analysis surface should distinguish:

1. Source
2. Observation
3. Interpretation
4. Open question
5. Confirmed claim
6. Unsupported claim

## Boundary check

Allowed line:

> System Analysis Reference is a neutral reference library for organizing evidence, timelines, claims, and observed system behavior without merging source, interpretation, and conclusion.

Avoid lines like:

> This proves misconduct.
> This is Perspection governance.
> This is Faceless Reclaimation testimony.
> This evidence speaks for itself.
> Everyone involved is guilty.
> This template is legal advice.

## Publish-safe description

System Analysis Reference is a neutral reference library for organizing evidence, timelines, claims, and observed system behavior without merging source, interpretation, and conclusion.

## Ultra-short description

Separate source, observation, and claim.

## Final pass questions

Before publishing, ask:

1. Does this separate source from interpretation?
2. Are unsupported claims clearly labeled?
3. Are confirmed claims supported by sources?
4. Is the material structural rather than performative?
5. Are private identifiers excluded unless intentionally necessary?
6. Does this avoid becoming legal advice or public accusation by default?

## Operating rule

This repository observes patterns.

It does not prosecute them.
It does not dramatize them.
It does not merge analysis with identity.

Claim, source, and interpretation must remain separate.
