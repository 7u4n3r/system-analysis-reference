# PUBLISH_ORGANIZE.md

## Purpose

This file defines the publish/organize posture for `system-analysis-reference`.

This repository is a neutral reference container for organizing observations, evidence structures, timelines, claim boundaries, and system-behavior patterns.

It may support legal, civic, institutional, or project analysis, but it should not become a public accusation archive or personal testimony container by default.

## Current public role

System Analysis Reference is a neutral structure library for:

- evidence organization
- timeline building
- claim/source/interpretation separation
- pattern mapping
- case-study templates
- procedural analysis
- institutional behavior observation

## Publish-safe description

System Analysis Reference is a neutral reference library for organizing evidence, timelines, claims, and observed system behavior without merging source, interpretation, and conclusion.

## What this is

This repo may hold:

- timeline templates
- evidence index templates
- claim-boundary worksheets
- source logs
- observation maps
- pattern analysis formats
- case-study structures
- neutral procedural breakdowns

## What this is not

This repo is not:

- Perspection governance
- Faceless Reclaimation story material
- Trinity Framework doctrine
- a legal accusation archive by default
- an unsorted evidence dump
- a place to publish raw claims without source separation
- a personal testimony container as the main identity

## Entry posture

The public posture should be:

- neutral
- source-aware
- claim-bounded
- organized
- calm
- structural
- careful about difference between observation, interpretation, and conclusion

System Analysis Reference holds structures for separating what was observed, where it came from, what it may indicate, and what remains unconfirmed.

## Core separation rule

Every analysis surface should distinguish:

1. Source
2. Observation
3. Interpretation
4. Open question
5. Confirmed claim
6. Unsupported claim

## Avoid these moves

Avoid:

- presenting interpretation as fact
- publishing accusation without source separation
- mixing personal testimony with neutral templates without labeling the shift
- using Perspection governance as the repo identity
- turning system analysis into Reclaimation story copy
- letting a case study become the whole project identity

## Related but separate

- Perspection holds governance and observation infrastructure.
- Faceless Reclaimation holds public story/artifact/Reclaimation material.
- Trinity Framework holds structural method and movement logic.
- Trinity Tools holds sandbox experiments and preserved drafts.
- KY County Map holds ABLE-KY county navigation.

## Pre-publish checklist

Before publishing material from this repo, confirm:

- [ ] source and interpretation are separated
- [ ] unsupported claims are labeled as unsupported
- [ ] templates do not include unnecessary personal identifiers
- [ ] legal conclusions are not asserted without source support
- [ ] related projects are labeled as related, not absorbed
- [ ] the material stays structural rather than performative

## Operating rule

This repository observes patterns.

It does not prosecute them.
It does not dramatize them.
It does not merge analysis with identity.

Claim, source, and interpretation must remain separate.
