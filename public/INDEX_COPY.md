# System Analysis Reference

Templates and structures for organizing evidence, timelines, claims, and observed system behavior.

System Analysis Reference holds structures for separating what was observed, where it came from, what it may indicate, and what remains unconfirmed.

It is built for careful organization under pressure, where clarity depends on keeping claim, source, and interpretation separate.

### Core separation rule

Every analysis surface should distinguish:

1. Source
2. Observation
3. Interpretation
4. Open question
5. Confirmed claim
6. Unsupported claim

### What lives here

System Analysis Reference may hold:

- timeline templates
- evidence index templates
- claim-boundary worksheets
- source logs
- observation maps
- pattern analysis formats
- case-study structures
- neutral procedural breakdowns

### What this is not

System Analysis Reference is not Perspection governance.

It is not Faceless Reclaimation story material.

It is not Trinity Framework doctrine.

It is not a legal accusation archive by default.

It is not an unsorted evidence dump.

It is not a place to publish raw claims without source separation.

### Entry posture

The surface stays:

- neutral
- source-aware
- claim-bounded
- organized
- calm
- structural
- careful about the difference between observation, interpretation, and conclusion

### Related but separate

Perspection holds governance and observation infrastructure.
